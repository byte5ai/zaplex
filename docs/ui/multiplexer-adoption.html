UI-Spezifikation — Bestehende tmux-/byobu-Sessions übernehmen

Platzierung

  • Pro verbundenem Host unter den nativen Zaplex-Sessions.
  • Eigener Abschnitt „Bestehende tmux-/byobu-Sessions“; keine Vermischung der Persistenzmodelle.

Aktion

  • Ein festes Terminal-Icon bleibt pro Zeile sichtbar und tastaturerreichbar; der lokalisierte Tooltip lautet „In neuem Tab öffnen“.
  • Der Sessionname erhält die flexible Breite; die Aktion verdrängt ihn nicht mit wiederholtem Text.
  • Öffnet eine klassische SSH-Session mit ZAPLEX_SESSION=1 und exakt adressiertem Ziel.
  • Nie innerhalb einer bereits laufenden Zaplex-Session verschachteln.

Zustände

  • Liste zeigt Name, Multiplexer-Typ sowie Fenster-/Clientzahl, sofern gemeldet.
  • Kein tmux/byobu installiert oder keine Session: Abschnitt bleibt verborgen.
  • Scan-/Attach-Fehler bleiben sichtbar und werden nicht als leere Liste dargestellt.

Abnahme

  • Erkennung läuft über den bestehenden authentifizierten Hostkanal, nie über lokales Shell-Raten.
  • Sessionnamen werden als Daten übergeben, nicht in Shelltext interpoliert.
  • Neue Arbeit nutzt weiterhin native Zaplex-Sessions; diese Fläche ist eine Migrationsbrücke.
