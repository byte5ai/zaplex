UI-Spezifikation — Startmenü für Tab und Pane, Tab als Pane

Startmenü (Tab und Pane)

  • #spec L1 „+“ (neuer Tab) und jede der vier Split-Richtungen öffnen dasselbe Startmenü. Einziger Unterschied ist das Ziel: neuer Tab bzw. neues Pane in der erfassten Richtung relativ zum auslösenden Pane.
  • #spec L2 Erste Ebene in dieser Reihenfolge: „Terminal“ (lokal), „Neuer Agent…“ (nur bei aktivem Cockpit), Kopf „Favoriten“ mit allen Host-Favoriten, danach „Weitere Hosts ›“.
  • #spec L3 „Weitere Hosts“ ist ein Untermenü mit genau den registrierten Hosts, die kein Favorit sind, in Registry-Reihenfolge. Ohne solche Hosts entfällt der Eintrag. Registry-Lesefehler zeigt eine deaktivierte Fehlerzeile statt der Liste.
  • #spec L4 Ein Favorit verbindet per Klick auf den Namen direkt; „⋯“ öffnet seitlich „Neuer Agent auf <Host>“, „Bearbeiten“, „Aus Favoriten entfernen“. Im Split-Menü zielen Verbindung und Agent auf das Pane.
  • #spec L5 Tab-spezifische Einträge (Tab-Konfigurationen, Docker-Sandbox, Worktree-Konfiguration, geschlossene Session wieder öffnen) erscheinen nur im „+“-Menü, unterhalb eines Trenners.
  • #spec L6 Keine Markierung „· Aktuell“ im Menü; die Pane-Kopfzeile nennt den Host. Abbruch (Escape, Klick daneben) erzeugt nichts.

Neuer Agent ins Pane

  • #spec L7 „Neuer Agent…“ aus dem Split-Menü öffnet die bekannte Startkarte. Der Start erzeugt genau eine Session an der erfassten Position; eine Auswahl mehrerer Konten wird mit Hinweis abgelehnt, die Karte bleibt offen.
  • #spec L8 Konto, Launch-Intent und Prompt-Vorbelegung hängen am neu erzeugten Pane, nie am zufällig fokussierten.
  • #spec L9 Ist die erfasste Position beim Start nicht mehr gültig (Pane geschlossen, Tab entfernt), startet nichts und ein Hinweis erklärt es.

Tab-Benennung

  • #spec N1 Unverändert gemäß #spec P3: Tabtitel folgt dem fokussierten Pane, expliziter Tabtitel hat Vorrang; jedes Pane zeigt Host · Verzeichnis in seiner Kopfzeile (Industriestandard Windows Terminal, iTerm2, tmux).

Tab als Pane (Maus)

  • #spec J1 Ein Klick aktiviert einen Tab beim Loslassen. Wird stattdessen gezogen, bleibt der bisher sichtbare Tab sichtbar.
  • #spec J2 Innerhalb der Tab-Leiste sortiert Ziehen wie bisher um. Verlässt der Zeiger die Tab-Leiste nach unten, zeigt das Pane unter dem Zeiger eine Drop-Zone über der Hälfte (links/rechts/oben/unten), in die der Tab eingefügt wird. Richtung wie beim Pane-Kopfzeilen-Drag.
  • #spec J3 Loslassen über einer Drop-Zone fügt alle Panes des gezogenen Tabs mit ihrem Layout als Split an dieser Kante ein; der Quelltab entfällt; Fokus liegt auf dem zuletzt fokussierten Pane des gezogenen Tabs.
  • #spec J4 Der sichtbare Tab ist nie Ziel seiner selbst: beim Ziehen des sichtbaren Tabs erscheint keine Drop-Zone. Loslassen ohne Drop-Zone ändert höchstens die Reihenfolge.
  • #spec J5 Überführen startet keine Verbindung, PTY oder Agent-Session neu; Host-Bindung, Verlauf, CWD, Entwurf und Dateimanager-Modus jedes Panes bleiben.
  • #spec J6 Ein Tab mit noch laufendem provisorischen Daemon-/Managed-Start kann nicht eingefügt werden (wie #spec R1 beim Fenster-Drag).
  • #spec J7 Gegenrichtung bleibt: Pane-Kopfzeile auf die Tab-Leiste ziehen erzeugt einen eigenen Tab.
  • #spec J8 Drop-Zone nutzt ausschließlich Theme-Rollen (Akzent als Rand und transparente Fläche); keine dauerhaften Farbränder.
Vorbilder: Windows Terminal (gleiches Profilmenü für Tab und Pane), VS Code und JetBrains (Tab in den Editorbereich ziehen, Drop-Rückmeldung zeigt die Zielposition), tmux break-pane/join-pane. Löst #spec P2 (Rechts/Unten) und PRODUCT §32 ab. Farben dieses Dokuments illustrieren Theme-Rollen und sind nicht normativ.
