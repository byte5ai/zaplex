# Zaplex 1.0 – Release-Bereitschaft

Dieses Dokument ist das Abnahmeprotokoll für genau ein gebautes Artefakt. Phase
A prüft den Quellstand und hält jede Laufzeitzeile offen. Erst nach einer
frischen Build-Freigabe wird in Phase B die Matrix gegen das erzeugte DMG
ausgefüllt.

## Integrationsbasis

Gate 0 endete mit `V1_BASE_SHA`
`7100184f190f4bdc476aeb6376a088fcedb44720`. `release/v1.0` basiert
nachweislich auf diesem Commit; alle 1.0-Arbeitspakete liegen danach.

## Neubewertung der inerten Warp-Stubs (#19)

Nach Fertigstellung des Cockpits wurde die frühere Aufschubentscheidung erneut
geprüft. Das Cockpit bezieht Sitzungen, Verbrauch und Preise ausschließlich aus
den lokalen CLI-Datenquellen in `zaplex_cockpit`; es verwendet weder
`AIRequestUsageModel` noch Drive-ACL-, Session-Sharing- oder Telemetrie-Stubs.

Die verbliebenen Stubs bleiben für 1.0 bewusst inert bestehen. Ihre Entfernung
brächte keinen Nutzergewinn, würde aber weiterhin tief in funktionsfähigen
Bestand eingreifen: `AIRequestUsageModel` in 21 Dateien, die Shareable-Typen in
bis zu 19 Dateien, `SharedSession` in 43 Dateien und `TelemetryEvent` in 134
Dateien. Eine spätere Entfernung ist reine Codehygiene und muss je Bereich als
eigenes, regressionsgeprüftes Arbeitspaket erfolgen.

## Test-Evidenz

Der Implementierungsplan benennt 111 Rot-Tests. Phase A löst jeden Namen auf
eine tatsächlich vorhandene Rust-Testfunktion oder einen ausführbaren
Release-Check auf. Präzisierte Implementierungsnamen sind im Verifier explizit
zugeordnet; ein fehlender Test, ein unbemerkter Rename oder ein veralteter Alias
lässt `planned_red_tests_have_authoritative_evidence` fehlschlagen.

Zusätzlich hält `1.0-open-issue-tests.json` die am 2. August 2026 live aus
GitHub gelesenen 147 Pflicht-Tests der Issues #125–#143 fest. Die
Owner-Korrekturen für #141 (110/20 ohne doppelte Reasoning-Tokens) und #143
(nur devhost/agenthost) sind darin explizit und werden von Phase A erzwungen.
Derselbe Snapshot erfasst die älteren offenen Issues #18, #19, #21, #38, #47,
#50 und #110–#120 mit ausführbaren Tests, Runtime-Zeilen oder einer expliziten
Entscheidung. Für #50 erzwingt der Checker die Owner-Entscheidung „Thumbnail
statt Temp-Pfad“ einschließlich nativer Bildübergabe an den CLI-Agenten.
