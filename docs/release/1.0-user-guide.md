# Zaplex 1.0.0 – Installation und Wiederherstellung

## Installation auf macOS

1. Das zu `v1.0.0` gehörende DMG aus der offiziellen
   [Zaplex-Release-Seite](https://github.com/byte5ai/zaplex/releases) laden.
2. Das DMG öffnen und **Zaplex** nach **Programme** ziehen.
3. Zaplex aus **Programme** starten. Das DMG ist mit Developer ID signiert,
   von Apple notarisiert und benötigt keine Umgehung der macOS-Sicherheitsprüfung.

Zaplex legt lokale Einstellungen und Zustandsdaten im Benutzerprofil ab. SSH-
Passwörter, Schlüssel-Passphrasen und OneKey-Zugangsdaten werden im macOS-
Schlüsselbund gespeichert.

## Erster Host

1. Im SSH-Manager einen Host mit eindeutigem Namen, Adresse, Benutzer und Port
   anlegen.
2. Passwort, privaten Schlüssel oder eine OneKey-Zugangsdatenreferenz wählen.
3. **Verbindung testen**. Ein unbekannter Host-Key muss ausdrücklich bestätigt
   werden; ein geänderter Host-Key ist ein harter Fehler und muss außerhalb von
   Zaplex geprüft werden.
4. Verbinden. Zaplex installiert den versionsgleichen Sitzungsdienst automatisch
   unter `~/.zaplex/remote-server/` auf dem Zielhost.

## Agenten und Konten

Claude Code und Codex laufen als unveränderte interaktive CLIs im Terminal.
Zaplex erkennt konfigurierte Konten, zeigt deren belegte Nutzung mit Quelle an
und startet eine Sitzung nur mit Fähigkeiten, die die jeweilige CLI wirklich
unterstützt. Zugangsdaten bleiben in den Konfigurationsverzeichnissen der CLIs
und werden nicht an einen Zaplex-Dienst übertragen.

## Wiederherstellung

- **Zaplex startet nicht:** App beenden, erneut aus **Programme** starten und
  den Absturzbericht unter den lokalen Zaplex-Protokollen sichern. Die App nicht
  durch eine zweite Kopie aus dem DMG ersetzen, bevor die Zustandsdaten gesichert
  wurden.
- **Schlüsselbundzugriff verweigert:** In macOS den Zugriff für Zaplex erlauben
  oder den betroffenen Host auf eine andere gespeicherte Zugangsdatenreferenz
  umstellen. Ein fehlgeschlagener Schreibvorgang lässt den letzten gültigen
  Zustand bestehen.
- **Host-Key geändert:** Nicht blind bestätigen. Fingerprint direkt auf dem
  Zielhost oder über einen unabhängigen Administrationskanal prüfen und erst
  danach den gespeicherten Key aktualisieren.
- **Sitzung nach Netzverlust:** Den Host erneut verbinden und die vorhandene
  Sitzung öffnen. Zaplex bindet an die persistente PTY-ID und startet nicht
  ersatzweise eine zweite Agentensitzung.
- **Sitzungsdienst passt nicht zur App:** Neu verbinden. Zaplex ersetzt den
  Dienst versionsgebunden; falls das nicht gelingt, bleibt klassisches SSH als
  klar gekennzeichneter Rückfallpfad verfügbar.
- **Dateitransfer unterbrochen:** Den Eintrag in der globalen Transferanzeige
  prüfen. Wiederholbare Recovery-Einträge zuerst ausführen; Quelle oder
  vorhandenes Ziel nicht manuell löschen, solange ein Recovery-Pfad angezeigt
  wird.
- **Einstellungen oder Favoriten beschädigt:** Die gemeldete Datei sichern.
  Zaplex überschreibt eine als beschädigt erkannte Datei nicht automatisch.
  Anschließend nur die betroffene Datei aus einer bekannten Sicherung
  wiederherstellen.

## Update

Die App prüft GitHub-Releases, verifiziert die veröffentlichte Prüfsumme und
lädt das DMG. Der Austausch der App erfolgt bewusst über das sichtbare
macOS-Installationsfenster. Vor einem Update laufende Transfers abschließen und
wichtige Sitzungen so belassen, dass sie über ihre persistente ID erneut
angehängt werden können.
